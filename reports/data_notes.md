The recorder paces itself from `x-rate-limit-remaining` so credits last until the 00:00 UTC reset (`live.opensky_interval`).

## PIREPs (IEM archive + aviationweather.gov)

- IEM CSV contains stray `"` characters (e.g. `/TB "SO FAR SO GOOD"`), which break standard CSV parsing. The parser ignores quoting and splits the 5 clean trailing fields from the end.
- The same PIREP is reissued in several products (KMSC + KWBC). Dedupe on time, position, aircraft, altitude and intensity removes about 4% of rows.
- Turbulence text is free-form (`LT CHP`, `MD TURB`, `LIGHT TO MOD`, `MOD090`, `CONS LGT OCNL MOD`). Parse failure rate (has a `/TB` group but no intensity word): **0.4%** (2026-11-01), **1.0%** (2026-11-14).
- Includes AIREP-format reports with no slash groups (`... F360 ... TB NONE`); these are parsed too.
- **Mixed-intensity rule.** AWC's own decoder is inconsistent: `CONS LGT OCNL MOD` becomes LGT-MOD, while `OCNL LGT INTMT MOD` becomes LGT. We store both `tb_max` and `tb_min`. MOD+ defaults to `tb_max ≥ MOD`, and the `tb_min` rule gets its own benchmark row.

| UTC file | Reports | With TB | MOD+ (max rule) | MOD+ (min rule) | LGT+ |
|---|---|---|---|---|---|
| 2026-11-01 | 4,783 | 2,730 | 1,062 | 752 | 2,142 |
| 2026-11-14 | 2,768 | 1,215 | 345 | 255 | 886 |

PIREPs are biased toward bumpy air (MOD+ is 28–39% of reports that mention turbulence), so they can't be used as a base rate. Absence of a PIREP is weak evidence (SPEC §6.1).

## Vertical-rate quantisation (SPEC open question 1)

`state_vectors` / REST `vertical_rate` is in **m/s with 2 decimals**. Converted to ft/min, every ADS-B value lies within 1 ft/min of a multiple of 64. **The 64 ft/min step survives OpenSky's processing.** Sheppard's correction Δ²/12 = 341.3 (ft/min)² applies.

## adsb.lol daily history archives (candidate full-rate substitute)

- GitHub releases `adsblol/globe_history_2025` and `_2026`, one per day, about **3.5 GB/day** (global, two tar parts), **ODbL-1.0**. They cover winter 2025–26 (the jet-stream season in SPEC §3).
- Format: readsb `traces/xx/trace_full_<icao>.json` (gzip). Each point is `[dt, lat, lon, alt, gs, track, flags, baro_rate, {msg}, type, geom_alt, …]`, with typecode in the file header.
- Measured on 186 aircraft at FL200 or above (2025-12-30, 169k points): gap percentiles 10/25/50/75/90 % = **1.7 / 5.8 / 16.2 / 19.7 / 19.9 s**. Only 9% of gaps are 1.5 s or less. 92.8% of vertical rates are on the 64 ft/min grid.
- **First real day converted (2025-12-02):** 60,362 traces streamed, 13,992 aircraft in CONUS at FL180 or above, 12.3 M rows, 303 MB Parquet, 13 min end to end, peak RSS ~170 MB. 99.5% of kept baro rates are on the 64 grid (geometric rates are dropped; 12.9% of rows have no vr). **97.1% of rows carry a typecode**, versus 72% from OpenSky's 2024 DB, so the inline type fixes most of the UNK problem for this source. Gap percentiles at FL200 and above, 10/25/50/75/90 %: 2 / 8 / 19 / 20 / 20 s.
- **Full study window (2025-12-02 → 2026-01-15):** 44 of 45 days. **2025-12-31 has no release** (404 in both the `_2025` and `_2026` repos) and is a known gap in the train split. 2025-12-25 is published as a single `.tar` file rather than split parts; re-fetched after the fix (9,939 aircraft, 8.6 M rows, lower than the usual ~13–14k / 11–12 M, consistent with Christmas Day traffic).
- **Not 1 Hz.** readsb thins steady flight to about 20 s and adds points when values change, so sampling is denser when vertical rate jumps. This sampling depends on the signal and would bias variance statistics if treated as uniform.
- **The storage rule (readsb `globe_index.c`, `traceAddInternal`, dev branch, read 2026-11-15).** A new point is stored when the baro rate has moved **≥ 200 ft/min** from the last stored value (and then the buffered previous state is stored too), when altitude, speed or track change enough, or on the airborne heartbeat. MLAT positions are exempt from the rate rule. Checked on 2025-12-02 (ADS-B, FL200 and above):

  | Consecutive pair | n | Same vr | Change < 200 ft/min | Median change |
  |---|---|---|---|---|
  | 18–21 s apart (heartbeat) | 5.12 M | 63.8% | **99.5%** | 0 |
  | ≤ 3 s apart (triggered) | 1.58 M | 3.8% | 8.7% | 256 |

  So the archive is the 1 s vertical-rate series compressed with a **200 ft/min dead band**. **Decision (M2):** rebuild a 1 s series by holding each stored value until the next point (`core/hold.py`), up to `hold.max_gap_s` = 25 s; longer gaps are coverage loss and stay empty. Consequences: changes smaller than ±200 ft/min (about 3 quantisation steps) are invisible, so light turbulence is under-measured; single-step flicker never appears; Sheppard's 64 ft/min correction (B1) is a near-constant shift on this source. Only `adsb_icao`/`adsr_icao` rows are used (MLAT: 8 ft/min step, no dead band). These results must be re-run on full-rate Trino data when it is available.
- **Scale after holding (2025-12-02):** 166 M held aircraft-seconds, 44,812 flight-hours at FL200 and above, 27,679 of them in level segments (62%), 2.79 M aircraft-minutes. Scoring one day takes ~3 min and peaks at 1.4 GB.

## Method notes from M2 core (synthetic checks)

- **Sheppard validity.** On band-limited synthetic turbulence (0.1–0.4 Hz) quantised to 64 ft/min, Sheppard-corrected σ is within 2% of the unquantised value for σ ≥ 40 ft/min. Raw σ is high by +8% at 40 and +3% at 64. Below ~0.6 Δ it over-corrects (σ = 20 → −52%), because the error is no longer independent of the signal. Small corrected values therefore mean only "near zero".
- **Sparse sampling.** At 20 s spacing the SPEC windows (31 s trend, 15 s stat) hold fewer than 6 samples, so the statistic is undefined. Rate-specific windows are required (e.g. 600 s / 300 s recovers σ = 150 within 20% at 20 s spacing). This is part of the M3 rate-gap benchmark.
- **H3 res 4.** SPEC says "~22 km edge" (old H3 v3 table). h3 v4 gives **26.07 km** average edge and ~1,770 km² area. Cell size is unchanged; only the quoted edge was off.

## Trino (full rate)

Access approved 2026-11-15. `ingest/historical.py` fetches through `pyopensky.trino.Trino.history()` (partitioned, explicit columns, FL180 filter on the server), one hour at a time, into `data/historical/`.

Expected scale (to be replaced by measured numbers): ~2,500 aircraft at FL180+ × 3,600 s ≈ 9M rows/hour. If Parquet comes out near ~200 MB/hour, the 1,080-hour study window would be ~200 GB, more than the ~69 GB free. The smoke test measures the real numbers, and the download scope is chosen from them.

**First smoke run (2026-11-15 ~07:00 UTC): refused.** The browser login worked (Trino assigned query IDs), but every query came back `PERMISSION_DENIED: Access Denied: Cannot execute query`. Trino runs this check before it looks at any table, so the cause is the account's permissions, not the query or the date range. No data was returned. The fetcher now stops on the first such error instead of retrying.
Second run at 07:11 UTC (one login, token cached, stopped after one query): same refusal (query `20261115_071114_19339_52riq`). The cached token is a server-encrypted JWE, so its roles can't be inspected locally. Waiting on OpenSky to activate query permission.
